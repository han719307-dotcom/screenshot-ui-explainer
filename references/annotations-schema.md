# annotations.json 数据格式

一份 JSON 同时驱动 PNG 标注图与 HTML 交互页面。脚本将原图像素坐标自动换算为百分比，
因此 `x` / `y` / `label_x` / `label_y` **一律填原图像素坐标**，不要手工换算。

> **`x`/`y` 与 `label_x`/`label_y` 的区别**（最容易搞混的一处）：
> `x` / `y` 是**元素自身的定位点**（一般取元素视觉中心），回答"这条标注指的是哪里"；
> `label_x` / `label_y` 是**圆点实际画在哪**。两者相距超过 60px 时脚本自动画引线指回来。

## 顶层字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `annotations` | ✅ | 标注条目数组 |
| `group_notes` | ✅ | 分组功能说明。`{ "组名": "这块地方是干什么用的……" }`，每组 50-90 字。PNG 与 HTML 都会渲染在分组标题下方 |
| `source` | 建议 | 原图路径。写进去后调用脚本无需重复传 `-i` |
| `title` | 建议 | 图例面板标题 / HTML 页面标题，默认「界面标注」 |
| `subtitle` | 可选 | 副标题，显示在图例标题下方与 HTML 顶部徽标里。适合放账号、页面名、主题 |
| `groups` | 可选 | 另一种写分组说明的形式：`[{"name": "顶部导航栏", "note": "……"}]`。与 `group_notes` 等价，同时存在时以 `groups` 为准 |

顶层也允许直接是**数组**（省略元信息）。此时必须用 `-i` 传原图，且不会有分组说明。

## 分组说明（group_notes）怎么写

这是"先讲区域、再讲控件"的关键一层，**每个分组都要写**：

| 要点 | 说明 |
|---|---|
| 长度 | 50-90 字，2-3 句。过长会挤占图例空间 |
| 视角 | 用「这块区域」的口吻讲**区域职责**，不要写成控件清单（那是条目 `desc` 的活） |
| 三要素 | 负责什么 · 什么时候用到 · 与别处的关系 |
| 禁止 | 不要重复组内某条 `desc` 的内容；不要照抄界面上的文字 |

例：

```json
"group_notes": {
  "顶部导航栏": "整个应用的全局控制区，任何页面都在最上方。负责跨页面的搜索、通知与快速跳转，也是进入 Copilot、新建内容和账号设置的唯一入口——找不到功能时先回这里。",
  "左侧边栏": "个人工作台的导航区，决定主内容区显示什么。上方是固定的全局导航（首页、动态流），下方列出你自己的仓库，用于在多个项目之间快速切换。"
}
```

PNG 版会自动按面板宽度折行；HTML 版渲染成带左侧色条的浅色提示块。未写说明的分组不会留空位。

## 条目字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `n` | ✅ | 编号。整数或字符串均可，全局唯一。建议按区域顺序连续编号 |
| `x` / `y` | ✅ | **元素自身的定位点**（一般取元素视觉中心）在原图上的像素坐标。引线的终点也是这里 |
| `group` | ✅ | 分组名，相同值自动归入同一图例分区；分组顺序 = 首次出现顺序 |
| `title` | ✅ | 条目标题，显示在图例中。建议 `英文原名（中文解释）` 格式 |
| `desc` | 可选 | 详细说明。**只在 HTML 中展示**，PNG 图例不显示。写「点了会怎样 / 该状态说明什么」 |
| `label_x` / `label_y` | 可选 | **圆点实际绘制位置**。用于把圆点挪开避免压字；不填则等同 `x` / `y` |
| `dot_r` | 可选 | 该条圆点的半径（原图像素）。不填则用 `--dot-radius`（默认 15）。窄区域塞不下时缩小它 |

### 圆点位置怎么定（`x`/`y` 与 `label_*` / `dot_r`）

按优先级依次尝试，能不动就不动：

1. **圆点直接落在元素上**——元素内部有空白（大按钮、输入框、卡片）时，只写 `x`/`y` 即可。
2. **缩小圆点**——窄条里的元素（顶栏图标、小胶囊），写 `"dot_r": 11`。
   编号字号会跟着圆点自动缩放，不会溢出。
3. **就近挪到留白处**——元素正上方 / 正下方 / 正右方，**控制在 60px 以内**，此时不画引线。
4. **挪到远处 + 引线**——元素周围实在没有留白时才这么做。`label_x`/`label_y` 与 `x`/`y`
   相距超过 `--leader-threshold`（默认 60px）时，脚本会自动画一条带白色描边的引线，
   并在 `x`/`y` 处画一个空心圆环标出元素真实位置。PNG 和 HTML 都会画。

> 引线是补救手段，不是常规做法。一张图上出现太多引线会让画面显得凌乱。

## 编号与分组策略

- **按区域顺序编号**：顶栏 1-11 → 侧栏 12-14 → 主内容 15-21 → …，图例从上到下读起来才连贯。
- **同组内按位置排序**：从左到右、从上到下，与视觉扫描顺序一致。
- **合并粒度**：一行紧邻的功能按钮可合并为一个编号，在图例标题里用 `/` 罗列，如
  `常用任务胶囊按钮` + desc 里写 `Debug / Agent / Create issue / Write code / Git / Pull requests`。
- **分组数量**：3-7 组为宜。界面简单时可只分 2 组。

## 完整示例

```json
{
  "title": "GitHub Dashboard 界面标注",
  "subtitle": "账号：your-name · 页面：个人 Dashboard（深色主题）",
  "source": "C:/path/to/github-dashboard.png",
  "group_notes": {
    "顶部导航栏": "整个 GitHub 的全局控制区，任何页面都在最上方。负责跨页面的搜索、通知与快速跳转，也是进入 Copilot、新建内容和账号设置的唯一入口——找不到功能时先回这里。",
    "左侧边栏": "个人工作台的导航区，决定主内容区显示什么。上方是固定的全局导航（首页、动态流），下方列出你自己的仓库，用于在多个项目之间快速切换。"
  },
  "annotations": [
    { "n": 1, "x": 44, "y": 41, "group": "顶部导航栏",
      "title": "汉堡菜单（☰）", "desc": "收起 / 展开左侧导航栏，让内容区更宽。" },

    { "n": 11, "x": 2490, "y": 42, "group": "顶部导航栏",
      "title": "头像菜单", "desc": "账号设置、切换账户、状态、退出登录等。" },

    { "n": 14, "x": 330, "y": 281, "group": "左侧边栏",
      "title": "仓库列表（空状态）",
      "desc": "No repositories found：这里本应列出你的仓库，当前账号下还没有仓库，所以为空。" },

    { "n": 29, "x": 999, "y": 1207, "group": "Getting started 入门清单",
      "title": "Create project 按钮",
      "desc": "绿色主按钮，一键创建新项目 / 仓库，是完成上面任务的操作入口。",
      "label_x": 890, "label_y": 1207 }
  ]
}
```

注意最后一条用了 `label_x`：`x` 仍是元素定位点（999），但圆点挪到左侧空白区（890）以免压住按钮文字。
两者相距 109px > 默认阈值 60px，所以这一条会自动带一条引线指回按钮。

### 窄区域的写法

顶栏这类只有 40-56px 高的区域放不下半径 15px 的圆点，用 `dot_r` 缩小：

```json
{ "n": 3, "x": 1356, "y": 29, "group": "顶部导航栏",
  "title": "帮助与设置图标",
  "desc": "两个并排的线框图标，宽度都只有 20px 左右。",
  "dot_r": 11 }
```

若元素周围连缩小后的圆点也放不下（例如顶栏最右侧的窄小图标），再挪到远处并用引线：

```json
{ "n": 4, "x": 1460, "y": 39, "group": "顶部导航栏",
  "title": "头像菜单",
  "desc": "点击展开账号菜单。头像只有 20px，圆点放到右侧留白区并用引线指回来。",
  "label_x": 1540, "label_y": 29 }
```

## 坐标换算规则

脚本内部按 `百分比 = 坐标 / 图片尺寸 * 100` 定位，所以：

- 多倍屏截图（如 2544×1378）直接填原始像素值即可，无需考虑 DPR。
- 截图被缩放/裁剪后再标注，坐标必须重新测量，不能沿用旧值。
- `locate_elements.py` 输出的 `center_x` / `center_y` 可直接复制进 `x` / `y`。
  它的 `center_y` 是回扫区间纵向范围得到的**真实中心**，不是行带中点；
  但纵向范围只能在 `--band` 内测量，所以行带的 y 上下要留余量。
- 扫描深色底和浅色底都可以用默认的 `auto` 模式；结果不理想时才试
  `--mode dark-bg` / `--mode light-bg` 配合 `--threshold`。

## 常见错误

| 现象 | 原因 |
|---|---|
| 圆点整体偏移 | 用了缩放后的坐标，或把百分比当像素填了 |
| 圆点压住文字 | 未使用 `label_x` / `label_y` 微调，也没缩小 `dot_r` |
| 圆点太小看不清编号 | `dot_r` 设得过小（建议 ≥ 10），或两位编号时未留余量 |
| 画面上出现意外的引线 | `label_*` 与 `x`/`y` 距离超过 60px 就会自动画线。不想画线就把圆点挪近，或用 `--leader-threshold` 调大、`--no-leader` 关掉 |
| 引线指错位置 | `x`/`y` 填的不是元素真实位置（引线的终点是 `x`/`y`，锚点圆环画在那里） |
| 图例分组乱序 | `group` 名称有细微差异（多了空格、中英文不一致）导致被当成两组 |
| 分组说明不显示 | `group_notes` 的 key 与条目 `group` 不完全一致（多空格 / 中英混写）；键必须逐字对应 |
| HTML 里 desc 不显示 | 字段名写成了 `description` 或 `text`，只认 `desc` |
| 图片打不开 / 白屏 | 顶层 `source` 路径不对，或用了相对路径但工作目录已切换 |
| 图例底部被裁掉 | 用了旧版脚本；新版会按内容自动加高画布 |
| 扫描结果连成一片 | 行带里本来没有留白，或 `--delta` 太小。可调大 `--delta`、缩窄行带，或改用显式 `--mode` |
